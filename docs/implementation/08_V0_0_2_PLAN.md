# Headbang Heroes — v0.0.2 Specification & Implementation Plan

> Status: PLAN (not started). Builds on the frozen `v0.0.1` POC ("Make The Headbang Fun", core
> feel validated). This document is the authority for v0.0.2 scope; canonical `docs/*_V1.md` specs
> win on any conflict per `AGENTS.md`.

## Theme

**"From validated toy to playable prototype."**

v0.0.1 proved the headbang is fun on desktop with keyboard. v0.0.2 makes the game (a) playable on
ANY input including touch/phone, (b) more readable during play, (c) more expressive/metal, and
(d) safer to ship-test — without touching the validated core simulation, timing, or scoring math.

## Guiding constraints (from AGENTS.md / canonical specs)

- Do NOT change neck physics, judgment windows, scoring, HYPE/Finisher math. Those are frozen-good.
- All new avatar/hair/UI/haptics work is **presentation/downstream only** — it must never feed back
  into timing, Motion Quality, or the neck simulation (`HAIR_SYSTEM_V1`, `GAMEPLAY_SCREEN_V1`).
- Keep systems small, testable, data-driven. New content = artwork + reusable config, not new code
  paths (`HAIR_SYSTEM_V1` architectural constraints).
- Input converts to song-time before judging (already true); touch must reuse the same path.
- Playtest/debug controls must be gated out of shipping builds.

## Success criteria (definition of done for v0.0.2)

1. The full loop is completable with **touch only** (no keyboard): bang, pause, retry, continue,
   activate THE BANG, adjust calibration — all reachable on-screen.
2. A **NEXT** cue previews the upcoming inversion so dense passages are preparable.
3. The **Results** screen is emotion-first (grade dominant + themed contextual line), not a flat
   text block, consuming the existing `RunResult` (no scoring recompute).
4. Hair reads as **delayed metal secondary motion** driven by neck state (lag → overshoot → settle),
   presentation-only, with at least the Bald/Short/Medium/MediumLong/Long validation tiers.
5. Optional feel polish (motion trail, micro screen-shake) present and tunable, off-by-default-safe.
6. Save is crash-atomic; playtest controls gated behind `DEVELOPMENT_BUILD`/`UNITY_EDITOR`.
7. EditMode tests green; new pure logic (hair solver, result-comment selector, touch-region mapping)
   unit-tested; independent sub-agent compile/contract audits per package.
8. `bundleVersion` = 0.0.2; CHANGELOG updated; merged to `main` and tagged `v0.0.2` only when all
   above hold.

## Packages

Each package: scope, canonical refs, deliverables, exit gate, specialist reviewers. Execute one at
a time; stop at each exit gate for confirmation (same cadence as v0.0.1).

### P08 — Touch Controls & On-Screen UI  *(highest priority; unblocks phone testing)*

**Goal:** every playtest/loop action reachable by touch; keyboard remains as a dev convenience.

Canonical refs: `GAMEPLAY_SCREEN_V1` (top bar, protected region, thumb space, lower playfield),
`GAME_FLOW_V1` (Results→Retry one tap), `PRESENTATION_ACCESSIBILITY_V1`.

Deliverables:
- On-screen buttons wired to existing public flow methods:
  - Gameplay: **PAUSE** (top bar), **THE BANG** button that appears/emphasizes only when HYPE READY
    (manual activation per `GAMEPLAY_SCREEN_V1`), never as a hit.
  - Pause overlay: **RESUME / RETRY / QUIT-to-select**.
  - Results: **RETRY / CONTINUE** as large, obvious buttons (one-tap retry).
  - Pre-song / song-select / home: **PLAY / START** buttons.
- **Bang input via touch regions** in the lower playfield mapped to L/R/U/D, using large invisible
  comfortable thumb zones (not tiny buttons); reuse the existing `HeadbangInput` song-time path.
- **On-screen calibration** control (± a step, shows current offset/latency) so the player can
  calibrate without `[` `]`.
- Buttons must respect the **protected gameplay region** (never cover face/neck/CURRENT/head path).
- Layout is portrait, thumb-reachable; values are tuning fields.

Exit gate: loop completable end-to-end with touch only in the Editor (mouse/simulated touch);
no button overlaps the protected region; keyboard still works; sub-agent contract audit clean.

Reviewers: Presentation/Avatar, Architecture Guardian, QA Guardian. (Input hardening cross-check.)

### P09 — NEXT Cue (preview)

**Goal:** a restrained preview of the next inversion so momentum can be prepared, per spec.

Canonical refs: `GAMEPLAY_SCREEN_V1` (CURRENT/NEXT, NEXT emphasis 25–35%, dense-chart readability).

Deliverables:
- A second, time-authority-free preview cue showing the **next** unresolved event's direction at
  reduced emphasis (smaller/dimmer than CURRENT), positioned in its cardinal zone.
- Driven from the existing scheduler/resolver look-ahead (no new time authority; render-only).
- Must not clutter dense passages — obey "readable as choreography, not a note highway."
- Tunable emphasis/lead; hides when no next event.

Exit gate: NEXT visibly previews the upcoming direction without competing with CURRENT; disappears
at end of chart; no impact on matching/scoring (verified). Sub-agent audit clean.

Reviewers: Presentation/Avatar, QA Guardian.

---

### P10 — Results Emotion-First

**Goal:** turn the flat results text into the three-act payoff, consuming existing `RunResult`.

Canonical refs: `RESULTS_SCREEN_V1` (Impact → Report → Rewards; result-comment tag system; hierarchy;
grade-scaled presentation; RETRY/CONTINUE), consumes `RunResult` + `GradeCalculator` + `ResultTag`s.

Deliverables:
- **Act 1 Impact:** dominant grade (S/A/B/C/D) rendered large + grade-scaled emphasis, score, and a
  **themed contextual line**.
- **ResultComment selector** (pure, data-driven): `id / minGrade / maxGrade / requiredTags[] /
  excludedTags[] / priority / textKey`; deterministic pick from the already-derived `ResultTag`s.
  Copy pool is content (text keys), not logic.
- **Act 2 Report:** the confirmed metrics laid out as a performance card (incl. WELL count).
- **Act 3 Rewards:** XP / HH / level / first-clear as already produced by ProgressionService.
- **RETRY / CONTINUE** as clear actions (integrates with P08 buttons).
- Must NOT recompute scoring/grade — renders the authoritative result only.

Exit gate: grade understood immediately, themed line varies by performance tags deterministically,
report complete, rewards separated, retry/continue one-tap. Pure selector unit-tested. Audit clean.

Reviewers: Meta/Profile, Presentation/Avatar, QA Guardian.

---

### P11 — Hair Secondary Motion (lag → overshoot → settle)

**Goal:** delayed metal hair driven purely by neck motion; the biggest visual-identity jump.

Canonical refs: `HAIR_SYSTEM_V1` (neck→hair→amplification; motion tiers Bald/Short/Medium/
MediumLong/Long; inversion behaviour; HYPE 10–20% modest; front/back separation; presentation-only).

Deliverables:
- Pure `HairStrandModel`/solver extension (already stubbed) consuming neck angle/velocity/
  acceleration + inversion, producing a small segmented chain response: continue-along-previous →
  snap/follow → overshoot → settle.
- **Motion tiers** as data-driven configs (segments/stiffness/inertia/bend/overshoot/settle) — at
  least Bald(0)/Short/Medium/MediumLong/Long for the validation set; Long Metal is the feel stress
  test.
- `HairPresenter` renders the chain (quads/line segments; no new physics engine); front strands
  more constrained to keep face readable.
- HYPE as a modest (~10–20%) presentation exaggeration only.
- Numerically stable (sub-stepped, dt-clamped), never writes domain, resets cleanly on retry.

Exit gate: on Long Metal, inversion lag/overshoot/settle read clearly and connect visibly to the
neck; bald still feels good (hair only amplifies); zero domain coupling (verified). Pure solver
unit-tested. Audit clean.

Reviewers: Presentation/Avatar, Architecture Guardian, QA Guardian.

---

### P12 — Feel Polish (optional, low-risk)

**Goal:** cheap punch that amplifies successful bangs. Presentation-only, safe defaults.

Canonical refs: `GAMEPLAY_SCREEN_V1` (readability dominant), `PRESENTATION_ACCESSIBILITY_V1`
(reduced-motion respect).

Deliverables:
- **Motion trail/streak** behind the head at high neck speed (TrailRenderer or few quads), tunable,
  respects a reduced-effects accessibility toggle.
- **Micro screen-shake** proportional to bang intensity (small, capped), off/scaled by the same
  accessibility toggle; never obscures the protected region.

Exit gate: effects scale with intensity, never hurt cue/head readability, obey reduced-effects
toggle, and are trivially disabled. Audit clean.

Reviewers: Presentation/Avatar, QA Guardian.

---

### P13 — Hardening & Ship-Safety

**Goal:** remove the known foot-guns before this becomes a device-test build.

Canonical refs: `SAVE_PROFILE_V1`, `TECHNICAL_CONTRACTS_V1`, deferred items in `errors to be fix.md`.

Deliverables:
- **Atomic save**: `FileSaveStore` writes temp then `File.Replace`/promote-after-success so a mid-
  write crash never loses the last known-good.
- **Gate playtest/debug controls** (R hard-reset, `[` `]`, F1, keyboard bangs) behind
  `UNITY_EDITOR || DEVELOPMENT_BUILD` so a shipping build can't desync `GameFlowController`.
- Optional: read-only scorer interfaces (`IScoringReadout`/`IHypeReadout`) exposed to presentation
  before more presenters (P08/P10/P11) consume them, to keep the domain boundary a build invariant.

Exit gate: save survives a simulated mid-write failure (test); debug controls compiled out of a
non-dev build; existing tests green. Audit clean.

Reviewers: Meta/Profile, QA Guardian, Architecture Guardian.

## Explicitly OUT of scope for v0.0.2

- iOS on-device validation / Package 07 (blocked on Apple signing; do after v0.0.2 makes the build
  touch-playable).
- Production art / real avatar rig / face-expression channel.
- Runtime HH-MIDI importer & authoring pipeline (stays offline heuristic for now).
- Multiplayer, accounts, store, campaign, leaderboards.
- `Time.deltaTime → AudioClock` migration for the neck sim (tracked; not required for these goals
  and higher-risk — defer unless a package needs it).

## Sequencing & rationale

1. **P08 Touch UI** first — it unblocks phone testing and everything else (P10 buttons depend on it).
2. **P09 NEXT** — small, improves the play experience immediately.
3. **P10 Results** — completes the loop's payoff; reuses P08 buttons.
4. **P11 Hair** — biggest feel/identity gain; independent of UI.
5. **P12 Polish** — optional, only if time; safe.
6. **P13 Hardening** — before tagging, so v0.0.2 is a safe base for the eventual device build.

Each package is committed in small semantic commits on the working branch, pushed after its exit
gate, with an independent sub-agent compile/contract audit + the listed specialist reviewers, exactly
as v0.0.1 was executed.

## Verification model

- No local dotnet/csc: verification is careful review + independent sub-agent audits (some can
  compile/run pure-domain EditMode tests with Unity's bundled Roslyn when the Editor isn't locking).
- New pure logic gets EditMode tests (hair solver step, result-comment selection, touch-region→
  direction mapping, atomic-save recovery).
- Scene changes are mirrored into the serialized scene where possible so the user can playtest
  without a full rebuild; note when a rebuild IS required (new GameObjects from the builder).

## Branch & release

- Work on `develop` (branched from `main` at `v0.0.1`); `main` + `v0.0.1` stay untouched.
- `bundleVersion` → `0.0.2` at branch start; CHANGELOG opens a `[0.0.2]` section, filled per package.
- Merge `develop → main` and tag `v0.0.2` only when all success criteria are met.
