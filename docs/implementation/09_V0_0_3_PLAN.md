# Headbang Heroes — v0.0.3 Specification & Implementation Plan

> Status: PLAN (not started). Builds on the frozen `v0.0.2` (playable prototype). This document is
> the authority for v0.0.3 scope; canonical `docs/*_V1.md` specs + ADRs win on conflict per
> `AGENTS.md`.

## Theme

**"Fix what we measured, and let the game grow."**  Two tracks:

- **B — Evidence-driven playability fixes.** The v0.0.2 diagnostic pass instrumented the MISS
  problem but did NOT fix it. v0.0.3 makes the small, deliberate fixes the data points to
  (`docs/DECISIONS/0002-miss-investigation-report.md`) — one at a time, each verified with the
  diagnostics we already built.
- **C — Authoring pipeline.** Replace the heuristic "kick+snare → L/R" chart generation with a real
  offline **HH-MIDI importer/validator** (`docs/HH_MIDI_STANDARD_V1.md`) so charts are authored
  choreography, and more than one song can be added properly.

Not device validation (Package 07) — still blocked on iOS signing. When unblocked, that becomes its
own milestone and will consume the diagnostics + the touch-geometry fix from track B.

## Guiding constraints (AGENTS.md / specs)

- Track B fixes must be **aimed by evidence**, not guesses, and must not widen timing windows to
  mask a problem. Each fix ships with a before/after diagnostic reading.
- The authoring pipeline is **offline (Editor)**; runtime NEVER parses MIDI (`HH_MIDI_STANDARD_V1`).
  MIDI → validator/compiler → `ChartDefinition` → immutable `RuntimeChart`.
- Keep the frozen-good core: neck physics, scoring/HYPE/Finisher math, judgment tiers unchanged.
  Timing windows may only change if the diagnostic evidence specifically justifies it (documented).
- No licensed audio/MIDI committed (keep gitignored, provenance recorded).

## Success criteria (definition of done)

1. The dominant MISS cause identified by a keyboard-vs-touch A/B is **fixed and re-measured**:
   direction-confusion and/or timing bias materially reduced, shown with diagnostic reports.
2. Touch direction resolution is correct on portrait aspect ratios (no pixel-vs-normalized skew),
   verified by expanded ResolveZone tests + the zone visualizer.
3. The pulse cue's strongest visual moment is an **instantaneous peak at the event** (plateau
   removed), verified by `SectorPulseCue.DiagTimingProfile`.
4. A real **HH-MIDI importer** turns an authored `*.hh.mid` (dedicated `HH_*` tracks) into a
   validated `ChartDefinition`/chart JSON, with clear validation diagnostics for malformed input.
5. At least **one song fully authored** through the new pipeline (replacing its heuristic chart),
   plus the existing WISH/Beyond charts regenerable via the importer or clearly marked legacy.
6. EditMode tests green; new pure logic (importer parse/validate, any geometry fix) unit-tested;
   independent sub-agent audits per package.
7. `bundleVersion` → 0.0.3; CHANGELOG `[0.0.3]`; merge `develop → main` and tag `v0.0.3` only when
   the above hold.

## Packages

### P14 — MISS root-cause fix (track B, do FIRST, evidence-gated)

**Goal:** run the A/B, then make the single fix the data indicates.

Refs: `docs/DECISIONS/0002-miss-investigation-report.md` (decision rules), diagnostics from v0.0.2.

Procedure (gate before coding): keyboard ~30 events + touch/mouse ~30 events, press P, compare.
Then apply ONLY the indicated fix:
- Many WRONG_DIRECTION (U/D→L/R) → **fix `ResolveZone` geometry in pixel space** (equal-pixel
  diagonal, not normalized), keeping cardinal behavior; re-verify with the zone visualizer + tests.
- Consistent timing bias → improve latency estimate / default calibration (no window widening).
- Keyboard good / touch bad → touch mapping/path.
- Both shifted → clock/audio/chart/cue alignment.
- Errors ~0 but cue feels off → **remove the SectorPulseCue hit-plateau** so the peak is at t=0.

Exit gate: before/after diagnostic report showing the targeted metric improved; no gameplay math
widened. Reviewers: gameplay-core, QA Guardian (+ presentation-avatar if cue/geometry).

### P15 — SectorPulseCue peak (track B, likely paired with P14)

**Goal:** make the cue peak instantaneous at the event (ADR-0001 intent), removing the ~±window plateau.

Refs: ADR-0001, `SectorPulseCue.DiagTimingProfile`.

Deliverable: reshape the pulse so scale/brightness culminate at t=0 and fall off symmetrically,
instead of holding peak across the whole hit window. Presentation-only. Verify with the profile
sampler at −240..+240 ms.

Exit gate: `DiagTimingProfile` shows a single peak at 0 ms, not a plateau. Reviewer: presentation-avatar, QA.

### P16 — HH-MIDI importer/validator (track C, core)

**Goal:** offline Editor tool: `*.hh.mid` → validated `ChartDefinition`/chart JSON.

Refs: `docs/HH_MIDI_STANDARD_V1.md`, `agents/hh-midi-validator.md`, `agents/chart-content.md`.

Deliverables:
- A pure **HH-MIDI parser** (dedicated `HH_*` tracks: motion events, directions, techniques,
  modifiers, Rest/Windmill intervals, timing metadata) → intermediate authored model.
- A **validator** with precise diagnostics (unknown/ambiguous notes, overlaps, out-of-range,
  missing metadata) — rejects malformed input with actionable messages (golden-sample regression).
- A **compiler** step producing the existing `ChartDefinition`/chart JSON the runtime already
  consumes (no runtime MIDI parsing).
- An **Editor menu** entry to import a `.hh.mid` → chart asset.

Exit gate: a known-good `.hh.mid` imports to a valid chart; malformed samples produce clear
diagnostics; pure parser/validator unit-tested. Reviewers: HH-MIDI-validator, chart-content, QA.

### P17 — First authored song through the pipeline (track C)

**Goal:** prove the pipeline end-to-end with one real authored chart.

Deliverables: author (or convert) one song's `*.hh.mid` with real headbang choreography (techniques,
accents, rests — not kick+snare→L/R), import it via P16, play it. Mark the old heuristic charts as
legacy or regenerate. Keep licensed audio local/gitignored.

Exit gate: the authored song plays with a coherent, musical chart from the importer. Reviewers:
chart-content, rhythm-audio, QA.

### P18 — Consolidation & tag

CHANGELOG `[0.0.3]`, bundleVersion 0.0.3, merge `develop → main`, tag `v0.0.3`. Only when P14–P17
exit gates are met.

## Explicitly OUT of scope for v0.0.3
- iOS device validation / Package 07 (blocked on Apple signing).
- Production art / avatar rig (placeholder cubes remain).
- New techniques gameplay (Half/Deep/Whiplash/Windmill) beyond what the importer needs to *encode*
  — implementing their gameplay behavior is later.
- Avatar customization, multiplayer, store, campaign.

## Sequencing & rationale
1. **P14** first — it's the highest-value fix and gated on a quick A/B we can do immediately.
2. **P15** — small, pairs naturally with the cue evidence from P14.
3. **P16** — the importer (biggest piece; unblocks content).
4. **P17** — first authored song proves P16 end-to-end.
5. **P18** — consolidate + tag.

Executed one package at a time, small semantic commits on `develop`, independent sub-agent audits +
specialist reviewers, stopping at each exit gate — same cadence as v0.0.1/v0.0.2.

## Verification model
No local dotnet/csc; verification is careful review + independent sub-agent audits (which have shown
they can compile/run pure EditMode suites headless with Unity's bundled .NET). New pure logic
(MIDI parse/validate, geometry) gets EditMode tests. Track-B fixes ship with before/after diagnostic
readings. Scene changes mirrored where possible; note when a rebuild is required.

## Branch & release
Work continues on `develop` (already ahead of `main` after v0.0.2). `bundleVersion` → `0.0.3` at
start; CHANGELOG opens `[0.0.3]`. Merge to `main` + tag `v0.0.3` when all success criteria hold.
